## Live claim

Large-MoE pretraining builds an overlapping routed atlas over state space. Post-training quality should therefore be judged by how it preserves, bends, or rewrites that atlas rather than by output behavior alone.

## Formal object -> observable map

- normalized routed states and tangent-visible expert update fields
- routed domains, overlap charts, adjacency, and set margins
- protected atlas drift channels: coordinate, boundary, transition, chart-content drift
- matched-success intervention testing for chart-preserving vs knowledge-expansive objectives

## Existing attacks

- the post already draws a hard theorem / hypothesis boundary
- it also already writes down five explicit ways the program could fail
- the ledger therefore mainly needs to preserve the exact empirical obligations, not invent new rhetoric

## Missing brutal attacks

- a probe family and pre-registered evaluation set for protected layers
- predictive comparison against generic baselines like weight distance or coarse router telemetry
- matched-success intervention experiments that test chart-preserving constraints directly
- one empirical bridge result that shows atlas-style diagnostics predict something real better than a simpler baseline

## Launch gate

- Green: ship as a theory-and-falsification program with explicit theorem / conjecture / measurement boundaries
- Red: presenting it as an empirically settled preservation theory before the probe and matched-success program exists
