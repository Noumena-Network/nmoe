## Live claim

The core contracts of the `nmoe` stack are research-validity gates, not just engineering preferences:

- exact resume must preserve the training trajectory
- config and checkpoint surfaces must fail loudly on mismatch
- distributed MoE eval must use a correctness-preserving execution mode

## Formal object -> observable map

- exact-resume state: model, optimizer, RNG, loader offsets, config fingerprint
- correctness test: fresh trajectory vs resumed trajectory equality over a fixed window
- distributed-eval contract: lockstep live eval vs invalid snapshot/sharded paths

## Existing attacks

- the post records the stale-prefetch counterexample that motivated the conservative loader contract
- the public code anchors the exact-resume and fail-loud surfaces

## Missing brutal attacks

- a fresh-vs-resumed equality test with receipts, not just code anchors
- a negative config-mismatch test that proves checkpoint validation fails loudly
- a distributed-eval negative test showing the wrong MoE eval path hangs or returns invalid results

- Green: ship as a systems-contract essay if the post is explicit that these are validity claims backed by code and by at least one concrete counterexample
- Red: treating it as closed empirical proof without the explicit test surfaces above
