## Live claim

A small-model speedrun is a useful architecture-research instrument only when it is anchored to a public baseline, scored on more than loss, and used with an explicit dense-vs-sparse swap contract.

## Formal object -> observable map

- speedrun report `R(m; C_train, C_eval) = (L_T, Q_T, S_T)`
- anchor gap `Δ_anchor` at a fixed horizon relative to a public dense reference
- target-rule version of the anchor: `target_loss = 3.28`
- objective vector `J(m) = (L_T, Q_T)`
- active-width swap contract `W_active`
- sparsity confound `tokens_per_expert ~ total_tokens * K / E`

## Existing attacks

- the post explicitly fails exact external parity on the historical dense lane and records the measured `+0.205` anchor gap
- it pins the public anchor as two surfaces: the June 2024 code neighborhood around `b6b0a0d` and the exact public log value `s:9536 tel:3.275959`
- it preserves the historical loss-only calibration lanes rather than hiding them, including the measured fact that those runs carried `eval_tasks = core` while still running with `eval_enabled = false`
- it upgrades the loop with a completed `3 x 3` closure matrix that actually runs end-of-run `CORE` across `dense`, `MoE-64`, and `MoE-256` in `bf16`, `fp8`, and `nvfp4`
- it closes the old `MoE-256` evidence gap by running a dedicated fixed-horizon lane instead of relying on the longer iso-tokens/expert slice
- it shows that the loss-side answer and the capability-side answer can disagree locally (`bf16`) and agree strongly (`fp8`)
- it shows that `nvfp4` changes the architecture story rather than simply shifting it, with no lane reaching target and `MoE-256` clearly healthier than `MoE-64`
- it keeps the systems tax visible via the historical throughput surface and keeps the signal-per-expert confound explicit via `K/E`

## Missing brutal attacks

- a direct anchor-gap ablation that removes the known architectural mismatches one by one (tied vs untied embeddings, GELU vs SwiGLU, vocab padding, μP)
- multi-seed closure reruns to test whether the current target-step and `CORE` orderings are stable rather than single-lane accidents
- alternate fair-match attacks on the swap contract (for example active params, total params, or iso-tokens/expert) to test whether the current dense-vs-sparse conclusions are axis-dependent
- same-surface throughput summaries for the eval-enabled `3 x 3` closure matrix so the systems answer is measured on exactly the same lanes as the capability answer

## Launch gate

- Green: the post pins the public anchor to an exact log path and value, preserves the historical anchor-gap story honestly, upgrades the speedrun with end-of-run `CORE` on a completed `3 x 3` architecture-by-precision matrix, and treats the resulting dense-vs-sparse conclusions as contract-specific rather than universal
- Red: treating the current anchor comparison as an exact reproduction claim, pretending the speedrun is loss-only after the closure matrix, or flattening the `bf16`, `fp8`, and `nvfp4` stories into one generic sparse conclusion
